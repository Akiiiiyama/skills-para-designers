# Identity interview

Ask in rounds of at most 4 questions. Offer examples so the person can react instead of inventing from zero. Write their answers down in their own words — those words become the brief and the reasons behind every token.

## Round 1 — purpose

1. What will this design system build first? (portfolio, landing page, app, slides, all of them)
2. Who will see it, and what should they feel in the first 5 seconds?
3. Do you already have anything you love and want to keep? (logo, color, font, a video, a photo)
4. Where do you work: code, Figma (which plan?), both?

## Round 2 — values

5. Pick 3–4 words you want your work to carry. Examples: clarity, warmth, rigor, play, calm, courage, craft, growth.
6. For each word: what would it look like on a screen? (e.g. "rigor" → strict grid, few colors; "warmth" → off-white paper, rounded corners)

## Round 3 — personality sliders (1–5)

| Left | 1 2 3 4 5 | Right |
|---|---|---|
| calm | | energetic |
| minimal | | expressive |
| warm | | cool |
| classic | | experimental |
| rounded | | sharp |
| light-first | | dark-first |
| quiet type | | loud type |

## Round 4 — references

7. Three references you love (site, poster, brand, film, place) and **why** each one.
8. One thing you do **not** want to look like, and why.
9. Any color or font you dislike?

## Round 5 — constraints

10. Accessibility needs (low vision, motion sensitivity, languages, right-to-left)?
11. Stack: React, Next.js, plain HTML/CSS, Webflow, other?
12. Do you want packages on npm one day, or just a repo for yourself?

## Identity brief (write back, get a yes)

> **[Name or working name]** is for **[purpose]**, seen by **[audience]**. It should feel **[3–4 values]**: **[value → visual decision]** for each. It sits at **[slider summary]**. It borrows **[what]** from **[references]** and avoids **[anti-reference]**. It keeps **[existing assets]**. It is built **[code-first / Figma-first]** because **[constraint]**.
